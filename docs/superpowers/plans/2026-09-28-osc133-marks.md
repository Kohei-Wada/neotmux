# OSC 133 marks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The host keeps the OSC 133 marks a shell sends, `neotmux.pane.marks` reads them, and `neotmux.commands` turns them into commands with a state.

**Architecture:** `TermState::feed` cuts each chunk just before every `ESC ] 133 ;`. Before each piece goes in, it sets the absolute line number of the screen's top row on the vt100 callbacks. The `unhandled_osc` callback then stores `{ line, col, kind, exit }` in a `Marks` store. The store keeps them in line order and applies the replacement rules, and marks are pruned with the history. `PaneRead::marks` reads the store. Lua gets the raw marks, and the runtime convention `neotmux.commands` interprets them.

**Tech Stack:** Rust (`neotmux-proto`, `neotmux-pty`, `neotmux-lua`), vt100 0.16.2, Lua runtime.

**Spec:** `docs/superpowers/specs/2026-09-28-osc133-marks-design.md`

## Global Constraints

- Work in the worktree `.worktrees/osc133` (branch `osc133`). Never touch the main checkout.
- A pane that never sends a mark behaves exactly as today, and `neotmux.pane.marks(id)` answers `{}`. An unknown pane answers `nil`.
- A mark's `line` uses the same absolute numbering as `neotmux.pane.history` and `plugin.stamps`: `dropped + index`, with the history's lines first and then the screen's rows.
- Marks that arrive while the pane is on the alternate screen are dropped.
- Store rules:
  - A new prompt (`A`) at line `L` removes every mark on a line after `L` (`> L`) before it is added. Marks on line `L` itself stay.
  - A second mark of the same kind on the same line replaces the first, and that includes `A`.
  - Marks on lines the history dropped are removed.
- Lua `kind` spellings: `prompt` (A), `input` (B), `output` (C), `done` (D). `exit` is present only for a `D` that carried an integer.
- `neotmux.commands` states:
  - `done`: closed by a `done` mark.
  - `running`: the newest command, with an `output` mark and no `done`.
  - `prompt`: the newest command, with no `output`.
  - `unknown`: a newer prompt arrived before any `done`.
  - A `done` mark with no prompt before it is skipped.
- One file = one type in every crate (`Mark`, `MarkKind` and `Marks` each get a file).
- No comments unless the why is non-obvious (one line). Match the surrounding prose-style doc comments.
- `make check` must pass at the end.

```rust
//! Cutting a chunk just before every OSC 133 it holds.
//!
//! A mark is numbered by the line the cursor is on when `vt100` hands it over, and that
//! number is only known between feeds (`crate::screen::evictions`). So each mark goes in at
//! the front of a piece of its own, before the piece has scrolled anything.

const OPEN: &[u8] = b"\x1b]133;";

/// The chunk in pieces, each after the first starting with `ESC ] 133 ;`. A chunk with no
/// mark is one piece, itself.
pub fn split(bytes: &[u8]) -> Vec<&[u8]> {
    let mut pieces = Vec::new();
    let mut from = 0;
    let mut search = 1;
    while search < bytes.len() {
        let Some(found) = bytes[search..]
            .windows(OPEN.len())
            .position(|window| window == OPEN)
        else {
            break;
        };
        let cut = search + found;
        pieces.push(&bytes[from..cut]);
        from = cut;
        search = cut + 1;
    }
    pieces.push(&bytes[from..]);
    pieces
}
```

```rust
//! The OSC 133 marks a pane's shell has sent, in line order.

use neotmux_proto::screen::{Mark, MarkKind};

/// What a shell said about its own structure: where its prompts, command lines and outputs
/// start, and how its commands ended. Kept by the rules a redrawn prompt needs — a prompt
/// replaces whatever is below it, since that has been written over, and a mark replaces one of
/// its own kind on its line — and let go of with the lines they are on.
#[derive(Default)]
pub struct Marks {
    held: Vec<Mark>,
}

impl Marks {
    /// The kind and exit status of an OSC 133 payload, as `vt100` split it on `;`, or `None`
    /// for any other OSC.
    pub fn parse(params: &[&[u8]]) -> Option<(MarkKind, Option<i32>)> {
        let [b"133", kind, rest @ ..] = params else {
            return None;
        };
        let kind = match *kind {
            b"A" => MarkKind::Prompt,
            b"B" => MarkKind::Input,
            b"C" => MarkKind::Output,
            b"D" => MarkKind::Done,
            _ => return None,
        };
        let exit = match (kind, rest.first()) {
            (MarkKind::Done, Some(status)) => std::str::from_utf8(status)
                .ok()
                .and_then(|status| status.parse().ok()),
            _ => None,
        };
        Some((kind, exit))
    }

    pub fn add(&mut self, mark: Mark) {
        if mark.kind == MarkKind::Prompt {
            self.held.retain(|held| held.line <= mark.line);
        }
        self.held
            .retain(|held| !(held.line == mark.line && held.kind == mark.kind));
        let at = self.held.partition_point(|held| held.line <= mark.line);
        self.held.insert(at, mark);
    }

    /// Lets go of the marks on lines before `first_held`, which the history no longer holds.
    pub fn prune(&mut self, first_held: u64) {
        let gone = self.held.partition_point(|held| held.line < first_held);
        self.held.drain(..gone);
    }

    pub fn between(&self, first: u64, last: u64) -> Vec<Mark> {
        self.held
            .iter()
            .filter(|held| (first..=last).contains(&held.line))
            .copied()
            .collect()
    }
}
```

```rust
    /// Feeds one chunk to the terminal. The history lines it pushes out of the front are
    /// counted on the way through ([`crate::screen::evictions`]), and it is cut before every
    /// OSC 133 so each mark is numbered against the history as it stands when the mark
    /// arrives ([`crate::parse::marks`]).
    pub fn feed(&mut self, bytes: &[u8]) {
        let (parser, dropped) = (&mut self.parser, &mut self.dropped);
        // The one rewrite on the way in, and the reason it is here rather than at the pipe:
        // it is about what the bytes mean to a terminal, which is this file's subject.
        self.hvp.rewrite(bytes, |piece| {
            for part in crate::parse::marks::split(piece) {
                feed_counted(parser, dropped, part);
            }
        });
        let first_held = self.dropped as u64;
        self.parser.callbacks_mut().marks.prune(first_held);
    }
```

```rust
/// One piece into the parser, with the offset pinned off zero so `vt100` counts the appends
/// and put back before anything else can read it.
fn feed_counted(parser: &mut vt100::Parser<Said>, dropped: &mut usize, bytes: &[u8]) {
    let screen = parser.screen_mut();
    let len_before = crate::screen::scrollback::len(screen);
    let resting = screen.scrollback();
    screen.set_scrollback(resting.max(1));
    let offset_before = screen.scrollback();
    parser.callbacks_mut().top = (*dropped + len_before) as u64;

    parser.process(bytes);

    let screen = parser.screen_mut();
    let offset_after = screen.scrollback();
    screen.set_scrollback(resting);
    let len_after = crate::screen::scrollback::len(screen);
    *dropped += crate::screen::evictions::dropped(crate::screen::evictions::Feed {
        len_before,
        len_after,
        offset_before,
        offset_after,
    });
}
```

`runtime/lua/neotmux/commands.lua`:

```lua
-- A pane's commands, out of the marks its shell sent (OSC 133): where each one's prompt,
-- command line and output start, and how it ended.
--
-- A convention, not a plugin: it registers nothing, and reads `neotmux.pane.marks` when asked.
--
--   local commands = require('neotmux.commands')
--   for _, c in ipairs(commands.of(pane)) do
--     -- c.prompt, c.input, c.output, c.done: line numbers, the way `neotmux.pane.history`
--     -- counts them, any but `prompt` possibly nil; c.exit: the status `done` carried
--     -- c.state: 'done', 'running', 'prompt' or 'unknown'
--   end
--
-- The marks are the shell's word and nothing else, so they are read as hints. A shell that
-- sends none has no commands. A command whose `done` never came — `ssh` or `bash --norc` run
-- inside a shell that marks, where the next prompt is the outer shell's — is `unknown` once a
-- prompt follows it, never `running` forever. Only the newest command can be `running`, and it
-- is for as long as it runs: there is no timeout.
local M = {}

function M.of(pane)
  local out, current = {}, nil
  for _, mark in ipairs(neotmux.pane.marks(pane) or {}) do
    if mark.kind == "prompt" then
      if current and current.state == nil then
        current.state = "unknown"
      end
      current = { prompt = mark.line }
      out[#out + 1] = current
    elseif current and current.state == nil then
      if mark.kind == "input" then
        current.input = current.input or mark.line
      elseif mark.kind == "output" then
        current.output = current.output or mark.line
      elseif mark.kind == "done" then
        current.done = mark.line
        current.exit = mark.exit
        current.state = "done"
      end
    end
  end
  if current and current.state == nil then
    current.state = current.output and "running" or "prompt"
  end
  return out
end

-- The newest command, or nil for a pane with none.
function M.last(pane)
  local all = M.of(pane)
  return all[#all]
end

return M
```
