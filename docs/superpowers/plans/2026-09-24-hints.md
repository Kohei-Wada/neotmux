# Hints — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two keys pick anything on screen. `neotmux.hints` finds the targets in the visible
panes, labels each with one or two keys, and hands the one you typed to whoever asked.

**Architecture:** A runtime module in the same place and spirit as `neotmux.list` and
`neotmux.prompt` — the host learns nothing. It reads panes with `pane.content`, draws labels
with `ctx:text` over a `ctx:tint`, takes the keyboard with `on_key`, raises a mode, and freezes
the panes it labelled so the screen cannot move under them. A shipped plugin gives it a key and
a default action; copy mode gets a jump built on the same module.

**Tech Stack:** Lua 5.4 against the existing ABI. No Rust, no new host surface.

**Spec:** Issue #32 is the argument. The ABI it uses is documented in `docs/plugins.md`.

## Global Constraints

- **Nothing in `crates/` changes.** If a task finds it cannot be done in Lua, stop and say so
  rather than adding to the host — the whole point of the issue is that the ABI already
  suffices.
- **Columns, never bytes.** A target's position and a label's placement are grid cells:
  `neotmux.width` is the measure, the way `neotmux.words` uses it. A line holding `あ` must
  still label correctly.
- Keys are the shipped vim four where they apply: `Esc` and `q` leave. Labels are typed as
  themselves.
- Every module is documented in its own header the way `neotmux/list.lua` and
  `neotmux/words.lua` are: what it is for, why the host has never heard of it, one example.
- Every task ends green: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --
  -D warnings`, `cargo test --workspace`. Two PTY tests
  (`socket::ending_one_session_leaves_the_other_typing_into_its_own_shell`,
  `terminal_restore::renders_output_written_in_the_same_batch_as_exit`) flake under parallel
  load — re-run alone before blaming the branch.
- Commit messages are prose in this repo's voice: a lower-case summary line that says what is
  true now, then why. No `feat:` prefixes, no Co-Authored-By trailers.

## Rulings made before the work starts

These answer the issue's open questions so no task has to guess:

- **A screen that moves under a label is worse than no label.** The module freezes every pane
  it labelled (`pane.freeze`) while hints are up and unfreezes on the way out, whichever way it
  leaves. Copy mode already does this for the same reason.
- **The label is drawn over the first cells of its target**, not before it. A label has to be
  attached to the thing it names, and one drawn in front runs into the previous word — and into
  the previous target, when two are adjacent.
- **`done` is the caller's, and the shipped plugin supplies the common actions.** The module
  answers with a target and nothing else; `plugin.hints` is what turns that into copying,
  sending to another pane, or opening.

### Task 1: `neotmux.hints`

**Files:**
- Create: `runtime/lua/neotmux/hints.lua`
- Test: `crates/neotmux-lua/tests/hints.rs` (create)

**Interfaces:**

```lua
local hints = require('neotmux.hints')

hints.open({
  panes   = 'visible',          -- default; or { id, ... }
  targets = { 'url', 'path' },  -- built-in finders by name; default is all of them
  -- find = function(pane, lines) return { { line =, col =, text = }, ... } end,
  done    = function(target) end,   -- { pane =, line =, col =, text = }
  cancel  = function() end,         -- optional; Esc and q
})
```

- `line` is the row within the pane, zero-based, as `pane.cursor` counts; `col` is the column
  the target starts at, counted with `neotmux.width`.
- Returns a handle with `close()`, idempotent, the way `neotmux.list`'s does.
- One hint session at a time; opening another closes the first.

**The built-in finders**, each a pattern over one line, exported as `M.finders` so a user can
add to the table or replace it:

| name | what it finds |
| --- | --- |
| `url` | `scheme://…` up to whitespace or a closing bracket |
| `path` | an absolute or `./`-relative path, `~` included |
| `hash` | a run of 7–40 hex characters — a git object, near enough |
| `ip` | four dotted numbers, optionally with `:port` |

**The labels:** the home row first (`M.keys = "asdfghjkl;"`, read on every open), one character
while there are few enough targets, two when there are not, and **no label a prefix of
another** — with two-character labels the first character is never also a whole label. The
nearest targets get the shortest labels: nearest means the focused pane first, then the row
closest to the top of the screen.

### Task 2: `plugin.hints`, and what to do with a target

**Files:**
- Create: `runtime/lua/plugin/hints.lua`
- Modify: `runtime/init.lua`, `runtime/lua/neotmux/defaults.lua`
- Test: `crates/neotmux-lua/tests/hints.rs`

**Interfaces:**
- Consumes `neotmux.hints` from Task 1, `neotmux.command.add`, `neotmux.clipboard.set`,
  `neotmux.pane.send`.

Three actions, each a registered command so the palette lists them, and `C-b f` for the one
people want most:

| command | what it does |
| --- | --- |
| `hint-copy` | the target's text to the clipboard — `C-b f` runs this |
| `hint-send` | the target's text into the focused pane, as though typed |
| `hint-open` | the target opened by the system — see below |

`hint-open` needs a process to run and this branch adds no host surface, so it goes as far as
the ABI allows: it writes an opener command into the focused pane with `pane.send`, which is
what a person would have typed anyway. Say so in the file's header rather than pretending it
launched anything; `M.opener` is the command, `xdg-open` by default.

On by default: it spends no screen space until the key is pressed, which is the bargain `copy`
and `sessions` are on for.

### Task 3: A jump in copy mode

**Files:**
- Modify: `runtime/lua/plugin/copy.lua`
- Modify: `docs/plugins.md`
- Test: `crates/neotmux-lua/tests/copy.rs`

**Interfaces:**
- Consumes `neotmux.hints`.

`f` in copy mode opens hints over the pane being read, with a finder that offers **every word**
(`neotmux.words` already says where they are) rather than the url/path/hash set — in copy mode
the thing you want is a position, not a token — and puts the copy cursor on the chosen cell.
That is the EasyMotion half of the issue, and it is three lines on top of Task 1.

Mind two things: copy mode has already frozen the pane, so the module's own freeze must be
idempotent (it is — `pane.freeze` answers `false` for a pane that is already frozen, and the
module must not unfreeze one it did not freeze); and copy mode is reading a *scrolled* view, so
the line a hint answers with is relative to what is on screen, which is what
`state.top` is for.

**Coverage:** Issue #32's wanted module is Task 1, with its four built-in finders, its labelling
rules and its column arithmetic; the default actions the issue asks about in its last open
question are Task 2; the EasyMotion reading — jump rather than act — is Task 3. The three open
questions are answered in the Rulings above rather than left to an implementer.

**Not covered, deliberately:** the issues that want to *consume* hints (#16's table rows, #19's
prompts, #20's lines, #23's paste) are not in this plan; each is a finder and a `done` on top of
what lands here. `hint-open` launching a process is not in it either — that is #13's jobs, and
this task says so instead of faking it.
