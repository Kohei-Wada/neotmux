# M1b — Budget and Overrun Policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A plugin tick that runs too long is cut off, its output for that frame discarded, the overrun attributed by name, and its tick subscription removed after repeated offences — reversibly.

**Architecture:** One global Lua debug hook fires every N instructions, reads the clock, and returns an error when the currently-dispatched source has exceeded its per-tick budget. The error unwinds through the host's protected call, so only that tick is rolled back. Overrun counts live beside the registry; crossing the limit removes the tick registration and nothing else.

**Tech Stack:** mlua 0.12.1 (lua54, vendored), `Lua::set_global_hook`, `HookTriggers::every_nth_instruction`, `std::time::Instant`.

**Spec:** `docs/superpowers/specs/2026-09-19-neotmux-design.md` §5 (and §4.5 for buffer epochs, §4.6 for the op buffer)

## Global Constraints

- `Lua::set_global_hook`, never `Lua::set_hook`. mlua's per-thread hook looks the current thread up in a weak registry table and, when it is missing, **silently removes the hook** — so `coroutine.wrap(function() while true do end end)()` would disable the budget in three lines.
- The hook performs **no Lua calls**. `luaD_hook` clears `allowhook` for its duration, so anything Lua-side inside it runs unmeasured. Rust only.
- The hook is a sampling point, not the accounting unit: it reads `Instant` and compares elapsed tick time against the budget.
- Defaults already exist in `crates/neotmux-lua/src/api/opt.rs`: `tick_budget_ms = 8`, `tick_overrun_limit = 5`.
- Overrun counters reset on any tick that completes within budget. Only the **tick** subscription is removed; keymaps, event handlers and status providers are untouched.
- Unsubscribing is reversible. Without a recovery path the only cure is restarting neotmux, which kills every shell the user is running.
- The host has no plugin concept. Identity is `SourceId`; names are display names derived from the chunk path.
- Tests pin behaviour, not structure. No speculative abstraction.
- No `#[allow(...)]`. `cargo test --workspace`, `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings` must be clean.

### Task 1: The budget hook

**Files:**
- Create: `crates/neotmux-lua/src/budget.rs`
- Modify: `crates/neotmux-lua/src/lib.rs` (declare the module; arm the hook in `build`)
- Test: in `crates/neotmux-lua/src/budget.rs`, plus `crates/neotmux-lua/tests/budget.rs`

**Interfaces:**
- Consumes: `Opts::tick_budget_ms` from `crate::api::Opts`; `SourceId` from `crate::source`.
- Produces: `Budget::new(Rc<RefCell<Opts>>) -> Rc<Budget>`, `Budget::install(&Lua, Rc<Budget>) -> mlua::Result<()>`, `Budget::enter(SourceId)`, `Budget::leave()`, `Budget::overran() -> bool`.

`enter` records the source and the start `Instant`. `leave` clears it. While no source is entered the hook does nothing at all, so key and event dispatch are unmeasured — the budget is a *tick* budget (§5.1).

- [ ] **Step 1: Write the failing test**

```rust
#[test]
fn a_tick_that_exceeds_its_budget_is_cut_off() {
    let lua = crate::vm::new_vm().unwrap();
    let opts = Rc::new(RefCell::new(Opts { tick_budget_ms: 5, ..Opts::default() }));
    let budget = Budget::new(opts);
    Budget::install(&lua, budget.clone()).unwrap();

    let spin: Function = lua.load("return function() while true do end end").eval().unwrap();
    budget.enter(SourceId::from_raw_for_test(1));
    let result = spin.call::<()>(());
    budget.leave();

    assert!(result.is_err(), "an infinite loop returned normally");
    assert!(budget.overran(), "the overrun was not recorded");
}
```

Do not add `from_raw_for_test`. Obtain a real `SourceId` by interning, as the other tests do.

- [ ] **Step 2: Run it and watch it fail**

Run: `cargo test -p neotmux-lua budget -- --nocapture`
Expected: FAIL — `Budget` does not exist.

- [ ] **Step 3: Implement**

`Budget` holds `RefCell<Option<(SourceId, Instant)>>` plus a `Cell<bool>` overrun flag and the `Rc<RefCell<Opts>>`. `install` calls `lua.set_global_hook(HookTriggers::new().every_nth_instruction(n), move |_lua, _debug| { ... })`, returning `Err(mlua::Error::RuntimeError(...))` when a source is entered and `start.elapsed()` exceeds the budget. Read `n` from a named constant with a one-line comment giving the measurement that chose it.

### Task 3: Overrun counting and reversible unsubscribe

**Files:**
- Modify: `crates/neotmux-lua/src/budget.rs` (the counters), `crates/neotmux-lua/src/lib.rs` (act on the limit), `crates/neotmux-lua/src/api/mod.rs` (the recovery binding)
- Test: `crates/neotmux-lua/tests/budget.rs`

**Interfaces:**
- Produces: `neotmux.resubscribe(name)` in the Lua API — `name` is a source display name; returns `true` if a tick subscription was restored, `false` if there was nothing to restore.

Note the spelling. §5.3 writes this as `neotmux.plugin.resubscribe`; there is no plugin
namespace and no plugin concept, so it goes at the top level. `neotmux.plugin.reload` is
**not implemented at all** — it is `package.loaded[m] = nil; require(m)` written in Lua, and
`docs/plugins.md` says so. Amend §5.3 accordingly as part of this task.

Restoring a subscription needs the callback to still exist after removal. Keep the removed
registration in the registry marked inactive rather than deleting it, or keep the registry key
beside the counter — choose one and say which in the report; do not build both.

- [ ] **Step 1: Write the failing test**

A tick that overruns `tick_overrun_limit` times in a row is absent from the tick subscriber list afterwards; exactly one notification names it; its keymap, registered by the same source, still fires.

- [ ] **Step 2: Run it and watch it fail**
- [ ] **Step 3: Implement the counter and the removal**
- [ ] **Step 4: Run it and watch it pass**
- [ ] **Step 5: Prove the counter resets**

`limit - 1` overruns, then one tick inside budget, then `limit - 1` more: still subscribed.

- [ ] **Step 6: Prove the recovery works**

After removal, `neotmux.resubscribe('plugin/spinner')` returns `true` and the callback runs on the next frame. Calling it for a name that was never removed returns `false` and changes nothing.
